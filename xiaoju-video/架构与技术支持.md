## 1. 它做什么、不做什么

做：
1. **刷视频网页**：打开网址随机刷「小橘视频」频道里的视频，上滑下一条、下滑回上一条。
2. **抖音转进频道**：频道主**自己**的抖音账号的作品（视频和图文）转进私有 Telegram 频道「小橘视频」。入口有：发作品链接、
   「转抖音视频」、每 30 分钟自动同步、云电脑全量抓取、发视频文件。
3. **搜抖音 → 审核 → 转**：搜关键词得到链接清单，频道主在审核机器人里点通过才转。
4. **内容过滤规则**：管理员在管理页配置，机器人只照着执行。

不做（都是实测或明确决定过的）：别人的作品批量搬；过验证码；不登录就自动发现新作品（抖音对没登录的访客藏起最新作品）；
用 Telegram 搜索查重（刚发的帖子搜不到作品号，会重复发）；音乐（那是 `../xiaoju-music/`，两个项目互不依赖）。

## 2. 总体架构

```
频道主 ──私聊/按钮──▶ 小橘视频机器人 ──webhook──▶ Worker ──X-Key──▶ 流式服务(Space) ──▶ 抖音网页版(无头 Chromium，不登录)
                                                  │  ▲                    │
                                                  │  └─ /streamer-up、/streamer-done（X-Key）
                                                  ▼                       ▼
                                      Durable Object(SQLite)       Telegram 私有频道「小橘视频」（用频道主账号 MTProto 发帖）
                                                  ▲
观众浏览器 ──▶ /video  /api/videos  /vf/<号>  /vp/<号> ──▶ Worker ──▶ Bot API(≤20MB) 或 流式服务 /vstream(>20MB)
云电脑(Codespaces) ──X-Token──▶ /dy-cloud-config /dy-import /dy-search /dy-progress /dy-known ──▶ Worker
审核机器人 ◀──webhook──▶ /verify-webhook ──▶ 同一个 Durable Object 里的审核任务表
```

| 块 | 代码在哪 | 跑在哪 | 干什么 | 状态存在哪 |
|---|---|---|---|---|
| Worker | `worker.js`、`verify.js`、`video.html`、`video-admin.html`、`douyin-login.html` | Cloudflare Workers（JS 模块） | 机器人、视频池、刷视频网页、审核、过滤规则、云电脑接口、定时任务 | Durable Object `Library`（SQLite） |
| 流式服务 | `streamer/`（`app.py` + `douyin/`） | Hugging Face Space（Docker，Python 3.12，端口 7860） | 无头 Chromium 取抖音、下载、ffmpeg、用频道主账号发进频道、超 20 MB 视频的按号取 | 只在内存和 `/tmp`，重启就没（所以有「接着转」机制） |
| 云电脑 | `cloud/` + 仓库根 `.devcontainer/douyin/` | GitHub Codespaces（2 核 4 GB，网页桌面端口 6080） | 在频道主自己的机器上登录抖音，MediaCrawler 抓/搜，结果送 Worker | `~/.xiaoju/`（令牌、已转作品号、进度、日志） |
| 刷视频网页 | `video.html` | 由 Worker 直接提供 | 随机刷、Range 播放、封面 | 浏览器 localStorage 里只放个人偏好 |
| 管理页 | `video-admin.html` | 由 Worker 直接提供 | 规则增删改开关、过滤记录 | 管理密钥存在**浏览器** localStorage |

技术栈：Worker 是原生 JS + `cloudflare:workers` 的 `DurableObject`；Space 是 FastAPI + uvicorn + Telethon（+ cryptg）+ Playwright
1.56（Chromium）+ ffmpeg；云电脑是 bash + Python + [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)。

## 4. Worker

### 4.1 路由和谁能调

| 路径 | 方法 | 谁调 | 认人方式 |
|---|---|---|---|
| `/`、`/video` | GET | 观众 | 无（公开，知道网址就能看） |
| `/api/videos` | GET | 刷视频网页 | 无。返回 `{videos, syncing, error}`；离上次和频道对账超过 30 分钟，顺带后台对一遍 |
| `/vf/<消息号>[.mp4]` | GET/HEAD | 网页 `<video>` | 无，支持 Range |
| `/vp/<消息号>` | GET | 网页 | 无，封面，取一次存库 |
| `/tg-webhook` | POST | Telegram（小橘视频机器人） | 请求头 `X-Telegram-Bot-Api-Secret-Token` = `TG_WEBHOOK_SECRET` |
| `/verify-webhook` | POST | Telegram（审核机器人） | 同一个请求头，值是接审核机器人时随机生成的 config `verifySecret` |
| `/admin`、`/video-admin` | GET | 管理员浏览器 | 页面本身公开，数据靠下面的接口认人 |
| `/admin/api/*` | GET/POST | 管理页、脚本 | `Authorization: Bearer <ADMIN_KEY>` |
| `/dy-cloud-config` | POST | 云电脑 | 第一次：`Authorization: Bearer <GitHub 令牌>`（须是 `langhua98`）；之后 `X-Token: <cloudTok>`，并带 `X-Busy` |
| `/dy-import` `/dy-search` `/dy-progress` `/dy-known` | POST | 云电脑 | `X-Token: <cloudTok>`；`/dy-import`、`/dy-search` 的 `X-Final: 0/1` 表示后面还有没有 |
| `/streamer-up` `/streamer-done` | POST | 流式服务 | `X-Key: <STREAMER_KEY>` |
| `/douyin-login`、`/dl/<令牌>/start\|status\|qr\|shot` | GET/POST | 浏览器扫码登录抖音 | 一次性令牌（config `dlTok`，15 分钟有效，机器人发「登录抖音」才生成） |

管理接口（`/admin/api/…`）：`videos`（GET 看数量和上次对账时间，POST 马上对一遍）、`filters`（GET 列、POST 加/改）、
`filters-delete`（POST `{id}`）、`filter-log?limit=`（最近的过滤记录，最多 500）、`douyin-self`（频道主自己的抖音账号 sec_uid，GET/POST）、
`douyin-search-queue`（GET 看排队的搜索词，POST `{clear:true}` 清空）、`douyin-auto`（POST `{on}`，自动同步开关）。

所有常量时间比较都用 `sameString()`；公开接口的 CORS 是放开的（`Access-Control-Allow-Origin: *`，只允许 GET/HEAD/OPTIONS）。

### 4.2 定时任务（`wrangler.toml` 的 `crons`）

| cron | 干什么 |
|---|---|
| `*/5 * * * *` | `checkResume`：有没转完的任务记录时，问流式服务现在在不在转；没在转就再交一次（流式服务重启后「报到」偶尔没送到的补漏） |
| `*/30 * * * *` | `expireReviews`（审核单 24 小时没审就作废）+ `douyinTick`（先 `checkResume`；开了自动同步就把自己账号的新作品转进频道，并更新频道里的置顶目录） |

`抖音自动同步 开|关`、`搜抖音 <词> [条数]`（`搜抖音 清空`）、`审核` / `审核机器人 <令牌>`；发抖音链接（作品或主页）、发 MediaCrawler 导出的
`.json/.jsonl` 文件、发视频文件（问一句要不要转）。菜单按钮和 `/crawl /progress /douyin /cloud /search /tags /help` 等价。
频道新帖（`channel_post`、`edited_channel_post`）只处理视频频道的，登记进视频池。

按钮：`fv:`（把发来的视频复制进频道）、`prg:`（进度面板：刷新/停云电脑/停小橘/运行爬虫）、`rvs:`（重新送审）、`rvt:`（再试转发）。

### 4.5 关键常量

`BOT_DOWNLOAD_LIMIT` 20 MB（Bot API `getFile` 上限，更大的走流式服务）、文件路径缓存 50 分钟、视频列表缓存 20 秒、
`VIDEO_SYNC_MS` 30 分钟（对账间隔）、对账失败 2 分钟后重试、对账最多等 120 秒、`STREAMER_WAIT_MS` 25 秒（等流式服务回响应头）、
`RESUME_MAX` 3（同一批最多自动接着转几次）、`SEARCH_DEFAULT` 100 / `SEARCH_MAX` 500、`MAX_SELVES` 30、审核单有效期 24 小时。

## 5. 流式服务（Hugging Face Space）

接口都要 `X-Key`（`hmac.compare_digest` 比较），除了 `GET /`：

| 接口 | 作用 |
|---|---|
| `POST /douyin/link` | `{text, target, notify, run_id?}`：作品链接 → 解析、下载、发进频道；主页链接 → 采集这个账号作品的公开链接 |
| `POST /douyin/resolve` | 只认链接（短链跳一次），不开浏览器：返回 `{kind: user\|aweme, id}`（添加账号用） |
| `POST /douyin/mirror` | 把一批账号能看到的作品按发布顺序转进频道，已有的跳过 |
| `POST /douyin/import` | 转云电脑抓来的作品；`final=false` 表示后面还有，边抓边转 |
| `GET /douyin/status` | 上一次的结果（`run_id`、`tags_used`、`worker_link`） |
| `POST /douyin/stop` | 取消正在跑的 |
| `GET /douyin/posted?target=` | 频道里已转过的作品号（查重；6 小时内只翻上次之后的新帖，最多翻 20000 条） |
| `POST /douyin/delete` | 删旧的抖音视频帖（换最高画质重转用） |
| `POST /douyin/login`、`GET /douyin/login/status\|qr\|shot\|state` | 登录页扫码登录抖音 |
| `GET /channels/owned?title=` | 在频道主自己建的频道里按名字找数字 id |
| `GET /vstream/<号>?target=`、`/vthumb/<号>?target=` | 超 20 MB 的视频按消息号取（Range，边取边传）/ 取封面 |
| `GET /videos?target=` | 翻视频频道里所有视频帖（刷视频网页的视频池对账用） |
| `POST /login/code`、`POST /login/verify` | 重新生成频道主账号的登录凭证（`TG_USER_SESSION`） |

环境变量（Space → Settings → Variables and secrets，**都设成 secret**）：`TG_API_ID`、`TG_API_HASH`、`TG_BOT_TOKEN`、`STREAMER_KEY`、
`TG_USER_SESSION`；可选变量 `WORKER_URL`。

内部要点（`douyin/job.py`、`app.py`）：
- 同时 3 条作品在「下载 → ffmpeg → 上传」（`AHEAD=3`），**发帖仍按顺序一条条发**，每条间隔 3 秒防限流；
- 视频本来就是 faststart 的不过 ffmpeg；>10 MB 的分 512 KB 一块并行上传，一条 8 块，整个服务同时最多 12 块；
- 单条失败只记那一条，**连续 5 条**意外失败（`MAX_ODD_FAILS`）才整批停；抖音要验证（滑块）立刻停，不去过验证码；
- 边抓边转：收到 `final` 或 20 分钟没再来作品才收尾；Telegram 限流（FloodWait）按它说的秒数等；
- 图文发成相册（一组 ≤10 张，WebP 用 ffmpeg 转 JPEG）；
- 免费 Space 闲置约 48 小时（`gcTimeout=172800` 秒）休眠，被唤醒前 Worker 先收到 503。

## 7. 关键流程

**A. 观众刷视频**：`/video` → 页面取 `/api/videos`（Worker 读视频池，必要时后台向流式服务 `GET /videos` 对账）→ 随机挑一条，
`<video src=/vf/<号> poster=/vp/<号>>`。`/vf`：≤20 MB 且有 `file_id` → Bot API `getFile` 取（失败再退到流式服务）；其余 →
流式服务 `/vstream`。流式服务答 404 `gone`（频道里删了）→ Worker 把它从池里去掉；Space 在休眠 → 503「大文件服务正在唤醒」，网页稍后重试。

**B. 新视频进池**：频道新帖 → webhook `channel_post` → `toVideo()` → `upsertVideo`；编辑后不再是视频的移出。机器人自己转过去的帖子
收不到 webhook，所以靠 A 里的定期对账补。

**C. 发抖音链接**：`ownerDouyin` → `douyinStart('/douyin/link')`（记一笔 `run_id` 备「重启后接着转」）→ Space：`links.py` 认链接 →
`web.py` 无头 Chromium 不登录打开网页版，接口签名交给页面自己的脚本 → `items.py` 挑不带水印的 H.264 → `job.py` 下载、faststart、截图 →
用频道主账号分块上传 → 发帖（文案 + `📹 抖音 @作者 · 日期` + 原视频链接 + `#账号标签`）→ 私聊通知 → `/streamer-done` 销记录。

**D. 转自己账号的全部作品 / 自动同步**：`转抖音视频` 或 cron → `/douyin/mirror`（账号 = `douyinSelf`，目标 = `VIDEO_CHANNEL_ID`）。
查重：翻频道，从帖子说明里的原视频链接认出作品号，已有的跳过。

**E. 云电脑全量抓取**：机器人点「运行爬虫」→ `dyCrawlReq=1` → 守候进程下次问 `/dy-cloud-config` 拿到 `crawl:true` → `crawl.sh`
（只抓频道里还没有的）→ 边抓边送 `/dy-import` → Worker 转 Space `/douyin/import`，第一批进来就开始转 → 抓完 `X-Final: 1`。

**F. 搜索 → 审核 → 转**：`搜抖音 词`（先过规则）→ 入队 `dySearchQueue`（交给云电脑前再过一遍规则）→ 云电脑搜 → `/dy-search` 分批送 →
Worker 去重、按点赞排序、私聊发链接清单 → 搜完整份 `submitForReview`（整理清单时再过规则）→ 审核机器人把清单发给频道主 → 点「✅ 通过」→
Worker 只认任务表里 `approved` 的，转之前最后再过一遍「过滤」规则 → `/douyin/import`。**任何一步出错都不默认通过**：送不到 → `paused`；
24 小时没审 → `expired`；不通过 → `rejected`；通过了但流式服务没接上 → 仍是 `approved`，给「🔁 再试转发」。

**G. Space 重启后接着转**：Worker 每交一个抖音任务都记 `run_id` + 原样请求（导入任务连作品数据，表 `dy_resume`）。Space 启动后依次等 5、20、60、120、300 秒再
`POST /streamer-up` 报到（交上就停），Worker 把没转完的原样再交一次（频道里已有的跳过）并告诉频道主；没交上回 `retry`，Space 过会儿再报。转完或出错
Space `POST /streamer-done {run_id}`（失败隔 0/10/60 秒重试）销记录；频道主点停，Worker 自己销；cron 每 5 分钟再补一次。同一批最多自动接 3 次。

**H. 登录抖音（可选）**：机器人发「登录抖音」→ 发回 `…/douyin-login#<一次性令牌>`（15 分钟有效）→ 网页上扫码 → 登上后 Worker 取回 cookie 存 `douyinState`，
之后每次调流式服务都带上（Space 重启丢了 cookie 靠它恢复）。不登录也能用，只是抖音只给第一页（18 条）、藏最新作品。

## 8. 内容过滤规则

- 规则只由管理员在 `/video-admin` 加、改、删、开关（表 `filter_rules`）；机器人只执行**已启用**的规则，不自己加规则、不扩大条件；规则每次现读，改了马上生效。
- 一条规则 = 名字 + 词（含任意一个就算命中，不分大小写）+ 查哪里（`keyword` 搜索词 / `caption` 作品文案 / `both`）+ 命中后（`filter`：不搜/不进清单/不转；
  `flag`：照常进清单，在审核清单里标「⚠️ 待人工确认」，由管理员决定）+ 可选的提示。作品没有文案、文案规则查不了时也只标待人工确认。
- 检查点共四处：发「搜抖音」时、排队的词交给云电脑前（`queueAfterRules`）、整理审核清单时（`submitForReview`）、审核通过转之前（`transferApproved`，这里只看 `filter`）。
- 代码里**固定**的只有一条：`BUILTIN_RULES` 里的「未成年人保护」（`MINOR_WORDS`，直接写明未成年人的词）。管理页里列出来、命中照样记录，但不能关、不能删、不能改。
- 第一次启动放进去的默认规则（`SEEDED_RULES`，「校服」的两条：搜索词默认关、文案标待人工确认默认开）和管理员自己加的一样可以改、关、删，删了不会再放回来（`filterSeeded`）。
- 每次过滤/标记写进 `filter_log`（规则、命中的词、哪一步、哪条作品或搜索词），管理页看最近 100 条。

## 12. 排障手册

先做这几步自检（把 `$` 开头的换成你的值）：
```bash
curl -s https://langhua1998-douyin-proxy.hf.space/                                   # 流式服务活着吗：{"ok":true}
curl -s -H "X-Key: $STREAMER_KEY" https://langhua1998-douyin-proxy.hf.space/douyin/status   # 在转什么、worker_link 通不通
curl -s -H "Authorization: Bearer $ADMIN_KEY" $WORKER/admin/api/videos                # 视频池多少条、上次对账
curl -s "https://api.telegram.org/bot$TG_BOT_TOKEN/getWebhookInfo"                   # webhook 地址、积压、last_error_message
curl -s -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" https://api.cloudflare.com/client/v4/user/tokens/verify
```
日志在哪：Worker → Cloudflare 控制台 Workers & Pages → 对应 Worker → Logs（或 `wrangler tail`）；Space → Hugging Face 的 Space 页 → Logs；
云电脑 → `~/.xiaoju/watch.log`；机器人 → 看 `getWebhookInfo` 的 `last_error_message`。

| 症状 | 多半是 | 怎么办 |
|---|---|---|
| 网页提示「大文件服务正在唤醒」 | 视频 >20 MB，Space 休眠了 | 等 1～2 分钟自动重试；或先访问一下 Space 域名叫醒它 |
| 网页没有视频、提示「视频列表暂时取不到」 | 视频池空且 Space 没连上（`vSyncErr` 有原因） | 看 `/api/videos` 的 `error`；Space 起来后 `POST /admin/api/videos` 马上对一遍 |
| 某条视频播不了、之后消失了 | 频道里删了，Worker 自动去掉 | 不用管 |
| 转到一半不动了 | Space 重启（推代码、平台维护、崩溃） | 一般 5 分钟内 Worker 会自己再交；同一批最多接 3 次，3 次还不行会私聊提醒，需要手动重发；发「进度」看 |
| 「进度」里 `worker_link` 报 SSL EOF | Space→Worker 握手偶尔断 | 已自带重试和 5 分钟补漏，一般不用管 |
| 机器人说抖音拦截/要验证 | 机房 IP 被抖音风控（滑块） | 整批停下是设计；改用云电脑抓，或直接发视频文件。不去过验证码 |
| 云电脑显示没连上 | Codespace 停了/没打开（90 秒内没来问算在线） | 在 GitHub Codespaces 重新打开（打开会自动连）；看 `watch.log` |
| 点了「运行爬虫」没开始 | 云电脑没开，或正在搜（搜索优先） | 「进度」看 `X-Busy` 状态；没开就等下次打开 |
| 搜到 217 条只收到 143 条 | MediaCrawler 重复写；按作品号去重；规则过滤 | 审核清单消息里有各项计数；`filter-log` 看被过滤了什么 |
| 搜索词被拒绝 | 命中了规则 | 管理页看规则；`filter-log` 看命中的是哪条 |
| 审核单 `paused` | 审核机器人没接、频道主没点「开始」、Telegram 出错 | 点「🔁 重新送审」；在审核机器人里点「开始」 |
| 审核通过了但没转 | 流式服务没接上 | 点「🔁 再试转发」 |
| 机器人不回话 | webhook 没设/secret 不一致/token 失效 | `getWebhookInfo` 看 `last_error_message`；重设 webhook。只有频道主能用 |
| 管理页「管理密钥不对」 | `ADMIN_KEY` 换了或输错 | 重设 secret；浏览器里存的旧值点退出重登 |
| Space 日志 `TG_USER_SESSION is no longer valid` | 登录凭证被 Telegram 作废（被踢下线） | `POST /login/code` + `/login/verify` 重新生成，更新 Space secret |
| 发帖报 FloodWait | Telegram 限流 | 自动等它说的秒数；每条间隔本来就有 3 秒 |
| `workers.dev` 打不开 | 中国大陆屏蔽 | 开 VPN，或给 Worker 绑自定义域名 |

## 13. 限制

- 刷视频网页没有登录，**知道网址就能看池子里全部视频**（`/vf/<消息号>` 的号是连续的）；这是设计（README：有链接的人都能看）。要私密得另加认人。
- 没登录时抖音只给第一页（18 条）、藏最新作品、单条详情对机房 IP 弹滑块，所以全量靠云电脑，也没有「新作品自动发现」。
- Bot API 只能取 ≤20 MB 的文件；更大的靠 Space，Space 免费版会休眠、会重启。
- 云电脑单个视频上限 1 GB；Codespaces 免费额度用完会停（不扣费）。
- Cloudflare 免费版每天 10 万次请求，刷视频每次 Range 请求都算一次。
- Durable Object 里的数据**没有做导出备份**：视频池能从频道重建，但账号、标签、规则、令牌这些设置丢了要重设。
- 云电脑令牌 `cloudTok` 目前没有换令牌的入口（`cloudToken()` 只在没有时生成）。
- 管理页的 `ADMIN_KEY` 存在浏览器 localStorage 里，公共电脑上用完要点退出。
